# 本地执行栅栏

根据 2026-10-13 用户提供的两组反例，仅采用以下方式继续 GTOS 原生集成。

- 阅读使用固定路径的 `Get-Content -LiteralPath` / `Get-ChildItem -LiteralPath`，限定目录，不递归扫描整个缓存。
- 禁止内联 `python -c`、多层 `bash -lc`、动态拼接 shell 命令和下载后执行。
- Python 使用固定 `/usr/bin/python3 -I -B`；不加载 `env.sh`，不继承 `PYTHONPATH`、代理、凭据、`LD_PRELOAD` 或 depot_tools 搜索路径。
- 子进程使用参数数组和 `shell=False`。先核对工具 SHA256、来源文件和明确的单个目标；不从失败日志直接抽出并执行命令。
- 编译阶段使用独立网络命名空间，无外部网卡和路由。隔离不可用则停止该次执行，不退回有网络的运行方式。
- 构建/验证输出限于工作区的明确新目录，检查路径和符号链接；不覆盖旧失败、磁盘镜像或缓存。授权的源码修改单独审查、核对原文件哈希并保留原版本，不由构建脚本隐含改写。
- 只编译本轮必要的对象，保留已有 GN 准备结果和已验收对象。完整目标重放时仍使用真实锁定配置。
- 不使用 sudo、管理员提升、全局执行策略修改、全局代理/防火墙修改或凭据读取。
- Git 推送和 QQ 通知属于独立外部操作，不能被构建脚本隐含触发；需要另行核对目的地及已有授权，QQ 继续遵守 02:00–09:00 静默。
