image: rebuild the fixed 61-input closure, and measure that it is the baseline plus this packet's changes

The packet asks two things that read as opposites: reuse valid unaffected
objects, and rebuild the fixed 61-input closure when the original producer
evidence is inadequate. They are one instruction with a measurement in the
middle, so this commit records the measurement.

For each of the 61 slots the closure built, the rebuilt object is compared byte
for byte against the baseline object the catalog carries for that token, and the
slot's real depfile -- the one the compiler wrote -- is intersected with the
files this packet changed. 58 slots reproduced byte-identically: same toolchain,
same profile, same source. Three differ, and each one has a file in its own
dependency set that this packet changed (gdt.o from src/gdt.cpp and include/gdt.h,
kernel.o from src/kernel.cpp and both changed headers, boot_diagnostic.o from its
source and its header). None differs without a cause. All five assembly slots
reproduced, the loader included.

That empty third class is the point. A prose claim that "only the changed objects
differ" cannot fail; a rebuilt object that differs for a reason the packet does
not explain would hide behind it. Since reuse would have produced the same image,
rebuilding everything costs only time and removes any object that would have to be
carried forward on trust.

The image was built from the committed worktree under the frozen contract, linked
by the real ld through the entry's own admission in the baseline spec's order, and
passes the Makefile's own static audit: 171 source/header files integer-only,
61 input objects, 65817 instructions, 11 FP instructions inside the exact
allowances.

The matrix now runs that image. It is the same sixteen scenes, and every row
produced the same byte counts it produced on the previous image, which is what a
correct rebuild of a behaviour-preserving change should look like. 163 of 163
verifier checks pass.

Two of the sixteen rows are new here. `ap-fresh-smp2` requires the real AP entry
to acknowledge freshly and park with no stale or foreign acknowledgement -- a
worker row proves the queue was served, not that the acknowledgement came from
this boot's processor into this boot's slot. `kernel-invalid` requires the
production parser to refuse a fixed illegal value before any self-test, which is
what 138's "illegal_option" record could not stand in for: that was the harness
refusing an unknown scene name, not the kernel refusing its input.

The matrix's command lines are derived from the scene declarations into a table
the runner reads. An earlier runner composed `serial bootdiag-stop=$STOP` itself,
which dropped the e99 scene's bootlog-fail token and ran the plain memory scene
under the e99 name; the row then failed for a reason that had nothing to do with
the kernel.
