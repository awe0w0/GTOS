# English / Simplified Chinese language foundation

This milestone provides allocation-free locale, Unicode, raster-font and bounded
pinyin modules for the modern GTOS desktop. Locale selection, query rendering,
input routing and persistent settings are integrated by the desktop/storage
layers. These modules do not localize boot diagnostics or claim a full IME,
universal Unicode text editor or arbitrary Chinese font coverage.

## Catalog

`include/i18n/catalog.h` exposes `gtos::i18n::Locale` (`English=0`,
`SimplifiedChinese=1`), `StringId` and `Text(locale, id)`. Every entry has explicit
English and Simplified Chinese values in `tools/i18n_catalog.json`. This includes
window/dock labels, onboarding, applications, monitor, settings, launcher,
confirmation dialogs, notices, package errors and VM/store statuses. GTOS, CPU,
BSP, MiB, KiB and physical key names remain technical names. English and 简体中文
are displayed as language autonyms.

Use `Text` for new fixed UI strings. `Translate` is an exact-English-match bridge
for existing status producers; it returns localized `UnknownStatus` when no entry
exists, never silently substituting an English label into Chinese UI. Use
`FindStringId` in tests to detect unmapped strings. Do not use the bridge for
user-authored text, arbitrary external application metadata or diagnostic codes.
The stock Catch title is 接球, with the `jieqiu` pinyin entry. Only the desktop
can verify whether a package is the bundled Catch before choosing its translated
metadata; generic external packages retain their own text.

To add labels, append entries (preserving established `StringId` ordering), run
`tools/i18n_generate.py`, regenerate the atlas, and run the tests. Persistence
must validate stored numeric locale values before selecting a locale; the catalog
itself is stateless and defaults invalid locale values to English.

## Strict UTF-8 and safe editing

`Decode` validates Unicode scalar values and rejects bad lead/continuation bytes,
overlong forms, truncated sequences, surrogates and values above U+10FFFF. It
never reads past its explicit `available` byte count. A malformed byte yields
`{U+FFFD, 1, false}` so renderers can advance safely; a NUL consumes zero bytes.
A renderer should also stop at its explicit byte/codepoint display budget.

`Validate` requires a terminator inside its bound. Every text function is bounded
(default 4096 bytes); callers pass actual capacities for fixed buffers.
`Copy` copies the longest valid prefix fitting both byte capacity and codepoint
budget, always terminating if capacity is nonzero. It stops before malformed or
incomplete input. `Append` validates both operands and changes nothing if the
whole source cannot fit. `Backspace` validates the buffer before removing one
complete scalar. `ContainsAsciiFold` starts and ends comparisons on scalar
boundaries and folds only ASCII A–Z. It supports literal Chinese substring search
without matching continuation bytes. It does not implement Unicode case folding,
normalization, grapheme clusters, combining-mark editing or bidirectional layout.
`ByteLength` counts bounded bytes; `CodepointCount` counts the valid prefix.

## Pinyin input contract

`PinyinComposer` is **36 bytes** on both test targets, with no heap use. Its
preedit stores at most 31 ASCII letters and supports an explicit, original GTOS
UI-oriented dictionary of **206 exact spellings and 359 ordered candidates** in
`tools/i18n_pinyin.json`. Candidate phrases contain only licensed atlas glyphs.
The dictionary is maintained as GTOS source, not copied from an external IME.

- Letter keys append lowercased pinyin to the preedit
- Exact spellings have 1–9 candidates; partial/unrecognized spellings have none
- `Space` selects the first candidate; `1`–`9` selects that numbered candidate
- `Enter` commits the first candidate, or explicitly commits the Latin preedit if
  there is no candidate. Once inactive, Enter is passed through to the application
- `Esc` cancels active composition without committing; when inactive it passes
  through so the launcher can close
- Backspace/Delete removes one preedit letter; when inactive the key passes
  through so the host can perform codepoint-aware deletion from committed text
- Invalid candidate numbers, unsupported punctuation/control during composition,
  full preedit and insufficient commit capacity return `Rejected`, preserve the
  preedit and produce no committed text
- `Select(index, output, capacity)` also supports clicking a visible candidate
- Committed output is UTF-8; buffers include space for the terminating NUL
- `Cancel` also belongs on focus/locale/input-mode switches, dismissal and queue
  overflow so stale composition cannot reach the wrong target

Useful phrases include `yingyong` → 应用, `yingyongchengxu` → 应用程序,
`shezhi` → 设置, `xitong` → 系统, `jiankong` → 监控, `neicun` → 内存,
`waiguan` → 外观, `huanying` → 欢迎, `zhongwen` → 中文,
`yingwen` → 英文, `jieqiu` → 接球, `wenjian` → 文件,
`shuru` → 输入 and `sousuo` → 搜索. `nihao`, `ninhao`, `xiexie`, `zaijian`,
`zhongguo`, `gongzuo` and `xuexi` support a few basic non-UI phrases.
The spelling `lv` represents lü; there is no tone entry, apostrophe segmentation,
word prediction, fuzzy spelling, automatic syllable segmentation, candidate
pagination, learning, personalization or network dictionary.

Before `Feed`/`Select`, give the composer the smaller of the commit buffer size
and the remaining query capacity. Then `Append` can atomically accept committed
text without losing preedit to a full query. Repeated key events must be handled
by the desktop input layer; the composer intentionally has no keyboard state.

## Font API and memory

`LookupGlyph(codepoint, scale, glyph)` performs binary search and returns the
packed alpha pixels, width, height and advance for non-ASCII atlas glyphs. It
supports separate 1×/2× rasters; a 3× renderer zooms the 1× raster. The caller
retains its ASCII font. On failure the result stays unchanged; explicitly look up
U+FFFD to display the missing-glyph square. `HasGlyph` and `CoversText` cover the
union of printable ASCII and the Han atlas, with newline handled as layout.
`GlyphCount`, `GlyphCodepoint` and `AtlasBytes` allow bounded inspection/testing.

The initial **440 glyphs occupy 319,440 read-only bytes**, including both raster
sizes, index and metrics. Catalog and dictionary add small read-only tables. No
complete TTC is embedded, no runtime caches/heap are required, and the painter
can reuse its existing framebuffer; 32 MiB guests remain a required integrated
acceptance test. `apps/fonts/han_manifest.json` is the precise generated source
and coverage manifest. The full license, source URLs and reproduction instructions
are in `apps/fonts/` and must accompany binary distributions.

## Verification

```
GTOS_I18N_SANITIZERS=1 ./tests/i18n_test.sh
GTOS_I18N_FONT=/path/to/NotoSansCJK-Regular.ttc ./tests/i18n_test.sh
```

The harness runs real modules as freestanding i386 and x86-64 executables,
optionally with ASan/UBSan. It tests every valid non-NUL Unicode scalar, malformed
and truncated UTF-8, overlong/surrogate/out-of-range rejection, explicit boundary
reads, all destination capacities, canaries, codepoint truncation/backspace,
all-or-nothing append (including self-append), ASCII-folded Chinese substring
search, all catalog strings and candidate glyphs, atlas pixel/metric bounds,
unsupported glyphs and every dictionary candidate. Composition tests cover
cancel, backspace, case, keys 1–9, space/Enter, unmatched input, full preedit and
commit buffer boundaries. Optional font regeneration is byte-for-byte checked
against the pinned font and rasterizer versions. Integrated desktop host and
QEMU tests must independently verify text painting, interaction and persistence.
