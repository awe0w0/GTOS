# 原生字符串扫描

本模块由完整 IA32 V8 目标第31次真实链接的 `sscanf` 首错驱动，实际消费者是固定
libc++ 的 `money_get<char/wchar_t>::do_get`，以 `%Lf` 转换规范化金额输入。
提供者位于[集成模块](../native_v8_integration/README.md)的 `native_scanf_libc`：
使用固定 LLVM `sscanf.cpp`、目标局部扫描头适配和完整 float/double/80-bit long double
转换后端，不替换为简化浮点解析器。

`probe/` 保存已在 GTOS CPL3 执行的六份源码。两次32M/单CPU、64M/四CPU冷启动
执行14个用户任务，四个正常任务各41项扫描，共164项；另有内存不足与恢复、输入
和格式读取页故障、输出写入页故障、扫描循环取消与恢复。16次精确Reap核对所有
保留的物理帧，任务使用私有CR3，整型peer与内核继续前进。长双精度用例包含
2^53+1、2^64−1与1+2^-63，避免降为double后仍被错误验收。

独立证据审查拒绝594个错误日志和5个不合格ISA样例。实际符号ELF中53个带长度
函数的13541条指令符合IA32/x87/SSE2范围；合并到代码段的只读数据不参与指令
分类。852字节是扫描提供者自身最大栈帧，完整调用链栈上界尚未证明。取消用例
证明扫描循环中的进程与堆区回收，不证明取消时内部扫描缓冲正处于分配状态。

第32次真实完整GN最终链接使用同一对象字节，保留5148条旧对象命令、原顺序输入
和引擎参数，输入哈希及旧缓存元数据一致；`sscanf`未定义错误已消失。实际新首错
为 `absl::base_internal::LowLevelAlloc::Free(void*)`，完整ELF仍未生成。

本地仓库的参数化[入口](../../tools/launch-native-scanf.py)与[验证工具](../../tools/verify-native-scanf.py)
已使用仓库夹具重新构建用户程序和私有验收内核，双冷启动及独立审查通过；对应的
私有与公开符号ELF、部署ELF分别逐字节一致。入口要求显式路径、输入manifest与
已验收工具状态的SHA，使用[输入清单](input-manifest.json)锁定消费文件。
当前入口只复用原真实编译上下文中的扫描器及九个支持对象，不支持任意新prepare
的迁移，也未重新编译完整GN目标或证明空白主机bootstrap。集成模块的源码锁保留
创建时的资格快照，补充的实际公开结果在本模块验收记录中。

仓库源码包的独立GN准备也已通过：5149条对象命令、依赖图和最终链接输入顺序
经输出路径归一化后一致。只显式固定宿主链接池为原来的3，以免探测宿主cgroup；
未执行新一轮全量编译。这项结果与原编译上下文中的客户机重放分别记录。

资格覆盖实际 `%Lf` 消费路径及列出的扫描用例；未覆盖的宽字符字符串扫描
（`%ls`、`%lc`）不能据此视为可用。该接口尚不是完整通用C扫描库。

证据哈希与范围见[acceptance.json](acceptance.json)，构建与
重放须遵循[执行栅栏](../../docs/native-command-execution.md)。完整V8 Isolate/JS、
网页浏览、视频及HTML5尚未通过，生产镜像与内核容量未改。
