# 原生哈希、质数与无符号排序

为完整V8链接的真实`__next_prime`阻塞，将固定上游libc++的`hash.cpp`、
`functional.cpp`和`algorithm.cpp`接入既有`native_cpp_libcxx`。保留原
C++26、无异常、命名空间及库配置；5167条旧对象命令和顺序保持，新增三条。

提供者与消费者使用真实GN配置比对、完整-M/-MD依赖和输入哈希终验。
缺少三提供者的链接必须失败；正向消费者使用已验收的实际入口、退出和
`ceilf`对象，保持整数支持归档为最后输入，无未定义符号。

测试程序覆盖0..4096与最大合法32位质数、14种长度与8种非对齐、空指针零
长度、页尾16字节哈希；排序覆盖10种规模和5种模式并独立检验多重集；真实
unordered_map/set覆盖插入、重复键、rehash、查找、删除、清空和析构。

八模式同时检查正常返回、质数溢出的真实abort、哈希读越界、只读排序写故障、
运行中取消、STL new耗尽、带活跃容器的页故障，以及malloc失败后释放重试。
不承诺无异常配置下STL分配失败可恢复。32M/1CPU与64M/4CPU的实际结果、
16次精确Reap、帧/堆/FP所有者回收和同伴存活证据见[验收记录](acceptance.json)。

完整40仍用同一实际目标重放，下一真实阻塞与非穷尽诊断在验收记录。公开源码
与测试字节对应检查不等于重跑公开GN或客体。观察到的栈用量不证明完整调用链
上界；多核QEMU配置不证明并行用户线程。本模块不新增文件服务或stock读回。
完整ELF、Isolate/JS、浏览器网页、视频和HTML5仍待验收，生产镜像未更新。
