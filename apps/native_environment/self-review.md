# 自审记录

以 dev a209741 为底，仅合入八个已验收内核源码文件。Runtime 的事件通知、
Wait/timeout/resleep 状态、StopGroup/Reap 事件清理与 FILE_DUP 均保留。

启动环境为每个进程拥有的无指针快照；可信启动输入在 Task 发布前复制或清空，
AddTask 失败清空并失效 FP，原 rollback 销毁地址空间。worker 访问 root 快照，
没有用户目标 PID 或更新入口。Assign 先验证后替换，原环境与输入自身别名不会
在验证失败时被破坏；读取完整验证后才写用户页，回收后清空槽位。

Task 初始化重置线程/进程 CPU 计数并指向自身，worker 发布前指向真实根 Task。
只在实际 Running 用户上下文的 timer 采样记账；线程移出调度后才销毁进程空间，
新槽初始化重新绑定 owner。CPU 单位/分数、溢出和 scope 校验来自原实现，未改算法。

Task 与 Runtime 布局改变后，所有 17 个内核 C++ 对象都按同一新头编译；旧布局
对象未混入。CPUState offset 断言不变，三个独立哈希汇编对象复用。完整 map 审查
涵盖两个内核各 35 个对象，FP 只在原明确允许的汇编边界，无新增豁免。

独立组合回归的 1252 输入、1313 别名、原缓存元数据及新/复用输出终验均通过。
两配置下环境/CPU 的 64 个上下文与事件的 18 个上下文保留全部原断言，含预期
故障；FP、帧、事件句柄/对象精确恢复。四次真实 V8 原根启动另有独立历史回执。

发现并修正的测试问题仅为诊断行插入竞争：64M 原始日志把 ENV SDK 拆成 E、
完整 CPU SAMPLE、NV SDK…，宿主严格解析正确拒绝。只保护三个原打印段，
移除新增 scope 后原源完全相同，未删除断言或清洗原日志；新目录完整重跑后通过。

公开内核文件及 probe/SDK/回执均逐字核对已验收来源，旧 canonical 四文件另存
工作区版本化副本，Git 基线也保留原件。源码晋升不改已执行脚本、失败、构建缓存、
工具、安全设置或生产镜像。普通提交/推送仍使用既有 dev 授权，不强推。

证据目录沿用既有事件模块的 gitattributes 保字节规则：CRLF 作为行尾识别，
