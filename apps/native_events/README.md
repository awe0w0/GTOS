# 原生 IA32 事件与内核等待

真实 Content 入口在 MessagePumpForIO/UI 和 Mojo 平台接口处报告缺口后，本模块补齐
消息循环所需的事件等待基础。它提供实际 GTOS 系统调用和调度器睡眠/唤醒，不把
Linux 的运行结果计为 GTOS 验收，也不代表完整消息泵、IPC、窗口输入或浏览器已运行。

## 接口与约束

`include/process/event_abi.h` 定义独立版本 1，系统调用号 `0x4741..0x4746`：
CREATE、DUP、CLOSE、SET、RESET、WAIT。EAX 返回有符号结果，其余通用寄存器
和段寄存器保持。CREATE 快照完整描述符，再验证并写入 32 位句柄；输出允许和
描述符重叠，跨 guard、只读代码页、坏版本/长度/flags 均不能发布半成品。

句柄与对象分开计数，最多 64 个别名和 32 个事件对象；句柄单调递增，保持正值，
不会在关闭或回收后复用。worker 使用实际进程 root 的所有权，没有用户传入的 PID。
DUP 可保留或收窄 WAIT/SET/RESET/DUP 权限。仅可信内核可显式向另一个 owner
授予别名，用户不能猜句柄或通过 DUP 越过 owner 边界。

手动事件保持信号，自动事件由一次成功等待消费，重复 SET 合并为状态。WAIT
接受 1..16 个句柄，先完整检查所有句柄和权限，再返回最低就绪索引。后面的坏
句柄不会让前面的自动事件丢失信号。超时以调度器实际投递的 PIT tick 为单位，
范围 0..0x7fffffff，0 是非阻塞检查，超时返回 -110；这不是毫秒或无限等待标记。

内核在同一 BSP IF0 临界区完成快照、状态检查、SleepTask 和调度，SET/CLOSE
通过 notifier 唤醒真实 Sleeping 任务。等待仅保留数值句柄和受保护的内核帧，
不保留用户页、对象槽指针或额外物理页。关闭正在等待的别名返回 BAD_HANDLE，
其他别名仍可继续使用。超时已变为 Ready 的任务不会被写帧；若内核管理代码
再次安排睡眠，睡眠次数校验还会排除旧事件记录，保留新睡眠和事件信号。

退出和页故障先终止整组，在安全的桌面/kernel CR3 上由 Reap 回收 owner 别名；
独立 peer 的引用和事件状态继续存活，最后引用才释放对象。

服务由显式 `NativeRuntime::AttachEvents` 在 Activate 之前安装，endpoint 必须
活到运行时结束。未安装时新系统调用返回 UNAVAILABLE，既有启动配置保留。
Makefile 自动收集新内核源文件；默认桌面尚未安装消息泵/IPC 的完整服务链。

## 已验证范围

真实用户 ELF32 经规范 NativeRuntime 装载，在 CPL3 调用新 ABI，并创建、join
及复用共享地址空间 worker。矩阵为 O0/O2 × 32MiB/smp1、64MiB/smp4，仍只在 BSP
执行。核心文件使用标量内核选项，四组均需完成输入及别名终验才算通过。

- 完整 wire/guard/只读输出检查，重叠输出、外 owner、权限收窄与 stale handle。
- 手动事件的两个等待者、自动事件每次只唤醒一个、预先 SET 和重复 SET 合并。
- WaitAny 全数组预检、最低索引、重复句柄、真实 Sleeping 状态及寄存器保持。
- 等待数组已经快照后，调用方改写并释放原 VM 页，后续 SET 仍正确唤醒。
- 关闭别名取消真实等待，PIT tick 回绕超时，以及旧记录不能干扰内核重新睡眠。
- 真实 32 对象/64 别名容量、最后正句柄及编号耗尽，拒绝后精确恢复。
- 正常 root、两个实际 Sleeping worker 的整组页故障、独立 peer 存活及最后引用释放。
- 每组 9 个 FP 上下文初始化/失效，无不变量失败；物理帧、句柄和对象精确归零。

这些检查不证明 C11 调用方、通用 SMP、多进程 IPC、共享页或完整浏览器能力。
事件只有有界状态，没有负载队列；不能把它当作 Mojo channel 或窗口事件队列。

## 证据与执行

probe 保存实际执行的用户代码、加载脚本和内核观察器；receipts 保存完整终验、
隔离守卫与退出结果，logs 保存四份原始客体日志。replay 是已执行的固定入口
快照，仍绑定工作区既有 Clang/QEMU/整数归档、规范源码和先前内核输入回执，
不是可任意换路径运行的通用构建器，也没有声明空白主机冷构建已通过。

所有构建遵守[本地命令栅栏](../../docs/native-command-execution.md)：固定工具摘要、
参数数组、Python -I -B -S、最小环境、独立无网络命名空间、no_new_privs、
Landlock 精确执行文件白名单，只写新的输出。未更新生产镜像或重启生产虚拟机。

下一步仍回到真实 Content 主线：把已验证事件接入实际上游等待/调度消费者，
补齐 Mojo 端点、共享页和窗口输入，再重编同一完整入口，推进本地 HTML/CSS/JS
显示与输入/DOM，之后继续 HTTP/HTTPS、视频及 HTML5。不能用本模块的通过替代
[路线 Issue #9](https://github.com/awe0w0/GTOS/issues/9)要求的浏览器级证据。
