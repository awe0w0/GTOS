# 原生基础类与匿名持久分配器

本模块补齐完整 FilePath、LocalPersistentMemoryAllocator 和 LLVM strnlen 的实际调用路径，
包含 GTOS 页粒度接口、独立原生入口、保护页和生命周期诊断。完整 V8 扩展根先前已经
运行；这里另外验证基础类的词法、UTF、映射、类型和析构行为。

## 实现与来源

`patches/` 保存完整上游实现及明确的 GTOS 条件分支。FilePath 保留原有路径算法，
GTOS 字符串采用原始 UTF 转换提供者；PMA 保留原有布局、迭代和类型更改算法。
`SysInfo::VMAllocationGranularity()` 返回真实 VM ABI 的 4096 字节页单位；该方法添加在
完整原始 SysInfo 文件的 GTOS 分支内，其他平台逻辑保持原样。

LocalPMA 的 1MiB 匿名区使用真实 VM 预留、分批提交和释放。前缀元数据单独占一页，
数据区 256 页，前缀只读；失败释放已预留区。`gtos_file_mapping.h` 只声明尚待实现的
文件 flush 接口；本模块的运行结论不涵盖 FilePersistentMemoryAllocator 的文件后端。

`upstream/` 保存固定版本的原始声明及 LLVM strnlen 源文件，许可证见 `licenses/`。
其余上游文件、工具、生成头和原生 SDK 由来源锁及回执绑定，不把摘取的同名类声明
作为原类替代品。

`probe/start.s` 沿用原生入口的 16 字节栈对齐调用体。入口在环境 bootstrap 和大块堆
启用后调用全部真实构造函数，再执行诊断和真实 exit。历史命名的 exit 结果/阶段变量
服务于已有退出提供者；该独立诊断没有原 V8 main 或 NativeEntry。

## 实际 CPL3 验收

- 32MiB/smp1 与 64MiB/smp4 各连续两轮正例，共四个原生上下文。
  每轮 121 条断言、86 次系统调用、两个真实构造函数，正常退出且无故障。
- strnlen 覆盖 14 项保护页及边界情况，包括未映射地址 max0、无 NUL 读至右边界、
  七种起始偏移、末字节 NUL 和提前终止。
- 完整 FilePath 类覆盖 21 项路径/UTF 情况及 32 轮长字符串拷贝、移动、追加和析构；
  保留重复分隔符、父组件和无效 UTF 替换字符的上游语义。
- 完整 LocalPMA 实际映射 257 页并成功分配 256 次。覆盖尺寸/类型拒绝、重复迭代登记、
  Reset/过滤/顺序、错误类型不清零、成功类型转换全载荷清零、耗尽与 MemoryInfo。
  析构后旧 VM 句柄失效，正常退出时动态页为零。
- 错误长度控制只包装诊断 API，保留真实 libc 和类对象。两轮均在第 4 条 max0 断言
  返回源码结束行 57，随后真实 exit57 和完整 Reap；比较仍要求精确错误值。
- 正例每轮分别恢复 4724/12908 空闲物理帧，负例恢复 4725；任务数回到一个独立 peer，
  FP 初始化/失效依次 1/1、2/2，无不变量失败，peer 与 PIT 继续运行。

既有可信配置仍为 4096 映像页上限、128 栈页、1024 运行时页；当前诊断映像 2253 页，
实际容量 3405，没有增加配额。smp4 配置使用现有 BSP 调度范围，不推导通用 SMP。
用户侧九个完整对象共 62878 字节代码经过逐字节指令审查；每个观察内核的 35 个真实
对象都完成完整审查，包含 14 个原始整数归档成员，没有归档跳过。

四次成功正例在后续回执中按原日志、映像、完整 MD 和源/产物哈希重新核对后复用。
只为完整宏结束行预期补测两次负例，未重新执行不变的成功正例。旧失败和严格拒绝
结果保留在工作区；不能把早先部分运行的退出码当成整个阶段验收。

## 正式图、证据与范围

`probe/BUILD.gn` 声明独立 test-only 编译目标，汇总根同时依赖原有完整 Content 图。
SysInfo 仍使用已有 base 成员；目标注册不等于整套 Content 已编译或运行。实际 GN
成员、字段、顺序、工具规则及新目标编译结果由对应回执和来源锁记录。

完整图包含 21498 个目标、2517 个文件；已有成员、顺序、字段与七种原生工具规则
保持一致。五个实际 C++ 对象完成完整 M/MD 依赖及符号审查，独立小写 `.s` 汇编
只有一个固定源码输入，没有 include/incbin。Clang 对该输入忽略 MD/MF；终验按
实际源码、正式成员行、命令和对象摘要核对，不补造不存在的 depfile。六个正式
对象与上述原生验收对象逐字节相同，因此继承对应指令和运行证据，未重复运行。

`acceptance.json` 概括验收范围；`source-lock.json` 固定公开副本与八个当前内核
接口文件。`receipts/formal-compile-partial.json` 保留首次因汇编 depfile 预期错误
而停止的回执；完整结论以 `receipts/formal-qualification.json` 为准。

`receipts/`、`logs/` 和 `provenance/` 保存原始证据及其来源，`replay/` 是固定已执行入口
的快照，引用本工作区的固定工具、源视图与缓存；不声明空白主机冷构建通过，也不
提供可任意更换目录执行的通用构建脚本。

执行遵守[本地命令栅栏](../../docs/native-command-execution.md)：固定工具与摘要、
Python -I -B -S、最小环境、静态参数数组、无网络命名空间和 Landlock 精确执行文件
白名单，仅写全新输出。生产镜像实际更新时再同步可见虚拟机，本模块未更新镜像。

后续继续真实文件映射/flush 及其他 SysInfo 原生后端，再推进 Content 首帧、DOM、
HTTP/HTTPS、视频和 HTML5。GTOS 原生浏览器仍未运行。
