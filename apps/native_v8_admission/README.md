# 真实 IA32 V8 大镜像装载

真实完整58的静态 V8 ELF 已在 GTOS CPL3 执行，完成全局初始化并进入 Isolate 创建。
本模块当时在 Isolate 对齐分配失败后发生空指针写入。后续已由
[原生脚本运行模块](../native_v8_launch/README.md)解决，并完成真实 Isolate、Context
与 JavaScript；本页保留原装载基线和失败证据。
本模块验收的是大镜像装载、权限、失败回滚、退出回收和普通入口兼容性。

## 容量与所有权

- 普通 `ValidateElf32` 和三参数 `CreateElf` 继续使用原有限制：256 镜像页，
  运行时还须在总预算内保留两页用户栈；文件上限仍为 2 MiB。
- 内核可显式传入镜像页预算，范围为 1–4096；超过 256 页时启用大镜像配置，
  文件上限为 16 MiB。没有向用户态开放提高预算的系统调用。
- 大配置按实际镜像页数分配总记录容量：镜像页 + 两页根栈 + 256 页运行时余量。
  上限 4354 条。单次 VM 提交的 256 页事务暂存限制保持不变。
- 每条所有权记录为 16 字节。普通进程使用原有内嵌数组；大进程从物理分配器取得
  连续、清零、仅 supervisor 可访问的元数据帧。逐页核对身份映射、分配状态及其
  与目录、共享/私有页表、用户数据帧的隔离；用户复制缓冲也不能别名到元数据。
- 批量 MapNewRange 先验证完整范围及冲突，再分配。中途失败撤回本次新增数据页
  和空页表，保留原映射及错误原因。ProtectRange 先检查全范围，避免部分改权限。
- 原有 Seal、CPL3 帧、FP、调度和 Reap 顺序保留。移除调度引用、回到内核 CR3 后，
  清零并归还所有数据页、页表、目录及额外元数据。大槽位可再次用于普通进程。
- 进程自查询的 maximum_pages 报告所属地址空间的真实总容量；普通进程仍为 256。

## 真实运行结果

输入 ELF SHA256：`6eb32fb64cb140cb526c64ce7b73dbe20638afae25b0f1fc913c78a4ad131c48`。
文件 12,927,508 字节，RX 2361 页、RW 22 页，共 2383 个镜像页。
旧校验器实际拒绝为 Elf32PageLimit，失败计划全零；显式预算 2382 拒绝、2383 接受。

实测初始驻留 2385 页，加目录 1 页、页表 4 页、元数据 11 页，共消耗 2401 个帧。
总容量 2641 条记录，没有把全部容量预分配成用户物理页。
32 MiB / 4 虚拟 CPU 配置中用户任务仍仅在 BSP 执行；35 次实际进程自查询一致报告
2641。停止时驻留 2403 页，其中动态页 18 页；页故障后 Reap 精确恢复空闲帧基线。
随后同槽位普通原生程序查询为 256 页、4 个驻留页、零额外元数据，并再次精确回收。

受控耗尽覆盖：只剩 11 个连续帧时元数据成功、目录分配失败，11 帧全部退回；只剩
3 帧时跨 PDE 映射在中途失败，新增数据及页表全部撤回。另覆盖预算上下界、空范围、
用户区越界、重叠、保护范围缺页、只读拒写及解除映射。

普通入口的必要回归为 single/thread 各 32 MiB/单 CPU 与 64 MiB/四 CPU：44 程序、
68 上下文、24 次 Join、44 次 Reap，文件句柄、FP 和物理帧均恢复基线。
这组使用自查询修正前的同一容量实现；最后仅修正自查询返回容量，并用上述真实
V8/普通槽位复用验证新分支。没有把未执行的组合记为通过。

## 装载基线当时的首次失败

真实故障 PC 为 `0x4015e699`，对应 IsolateData 构造器的 `movl $0,(%esi)`，ESI 为零。
同一锁定 ELF 的 Isolate::New 先请求 `posix_memalign(4096, 39144)`；非零返回后仍以
空指针执行构造。native-entry 阶段为 2，结果仍为 `0xffffffff`；#PF error=6，CR2=0。
64 MiB/单 CPU 与 32 MiB/四 CPU 重现同一故障，内核同伴继续调度，回收成功。

当前原生 C 堆固定为 64 KiB。39,144 字节虽小于单块上限，但失败还可能与先前存活
分配、对齐空隙或碎片有关；本组尚未记录失败时的空闲块，因此不将根因直接归为
某个容量常量。下一步在真实分配点记录请求、返回错误、存活/空闲及最大对齐块，
再决定必要的堆策略。没有扩大堆或修改 V8 引擎行为来绕过该失败。

## 证据与重放边界

`acceptance.json` 固定私有运行状态与源文件 SHA256；本目录保留实际客机日志、
`kernel.cpp` 和旧校验器夹具 `validator-kernel.cpp`。夹具使用真实 multiboot ELF，
`entry-symbols.h` 从该 ELF 的实际符号生成，并检查地址落在可写装载段。
私有入口及完整 M/MD、对象、指令审查和隔离记录保留在工作区
`artifacts/native-v8-admission-20261015-a`；缓存未清理。本目录不是无需工具链和
外部锁定 ELF 即可运行的独立浏览器包。

`large-01` 因未绑定 canonical readonly_abi.h 而停止，保留失败。补齐干净基线的
86 个头文件绑定后，large02 完成编译、CPL3、回滚和回收；large03 仅增加私有故障
寄存器观察；large04 补边界；large05 使用最终自查询修正和普通槽位复用。
large03 的阶段成功判据曾误写为 3，本次实际为 2、未计为成功；最终判据为完成
process-exit 的阶段 4、result=0、exit=0、无故障，当前明确未满足。

所有执行使用固定脚本与工具 SHA、Python -I -B -S、最小环境、无网络命名空间、
no_new_privs、精确执行文件白名单及 Landlock 仅新输出可写；不在宿主执行 V8 ELF。
