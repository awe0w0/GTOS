# 自审：宿主 NSS 构建配置

实际结论限于离线元数据及两个 Linux 次级工具链的 GN 配置，不能替代宿主库链接、
GTOS TLS 或浏览器运行验收。有效记录为 `graph-04`，完整驱动、GN 生成和两个描述
命令均返回 0，最终输入检查通过。

## 根因与边界

原先全局 `use_sysroot=false` 使 Linux 次级工具链的 NSS 配置尝试调用 helper。
GTOS 主工具链必须保持该值；全局改 true 曾被既有断言拒绝，旧失败保留。
当前仅在 Linux x86/x64 工具链的参数中，针对 GTOS 交叉目标启用固定 Linux sysroot。
没有修改 GTOS 的原生断言、目标身份或证书配置。

上游缓存只有 amd64 的传统输出路径条目。不能直接把它套给 i386 或当前私有布局。
新缓存值来自两次实际查询，路径前缀只重定位到已知只读源视图；原条目全部保留。
没有空结果、假成功、删除目标依赖或去掉 NSS 证书集成。

## 验证和保留的失败

1. `graph-01`：GN 拒绝覆盖默认非空 `configs`。新夹具先显式清空该列表，再仅选择
   真实上游 NSS config，用于隔离检验构建元数据，不声称验证默认全部编译配置。
2. `graph-02`：真实 GN 已生成，但终验发现 `v8_target_cpu.gni` 未预先绑定。补齐
   固定上游 Git 源码后使用新目录重放，不追认这次整体通过。
3. `graph-03`：生成与输入闭合已通过；描述命令遗漏私有根目标和点文件，重新加载
   默认根并被项目保护断言拒绝。当前版本的本地 GN help 已核对，`graph-04` 中
   生成与描述共用相同作用域参数，并均使用禁止 helper 的私有点文件。旧描述命令
   没有继承该点文件，其 helper 限制不能按生成阶段推断；该失败作为反例保留。
4. `graph-04`：真实 GN 生成 5 目标/43 文件，48 项实际依赖全部闭合。两个架构的
   真实描述结果逐项核对 include、库和 config，253 个绑定输入前后摘要一致。
5. 两文件补丁在全新目录执行 `git apply --check`、实际应用及字节比对。

读取工具帮助不加载工程。查询和 GN 使用不同精确执行白名单；父入口限制写入新输出，
拒绝源码写入，网络隔离与 Landlock 失败即停止。脚本不从日志取命令执行，不读取凭据，
不修改 Git hooks、全局配置或安全规则，旧失败和构建缓存保持。

Content 的 D-Bus/GIO 调整只针对 Linux 宿主可选桌面集成，GTOS 默认已关闭。
NSS 保留。最新图仍因 udev 探测失败，不能把首错变化当作完整 Content 验收。
完整 Rust std、libxml 原生服务、首帧/DOM、网络、视频与 HTML5 继续保留为未完成。
