# 原生底层分配器

第32次完整 V8 原生链接缺少 `LowLevelAlloc::Free`：固定 Abseil 根据平台能力
排除了实现。集成模块现在保留原 arena、skiplist、拆分、合并、锁和计数，接入
GTOS 的 VM reserve/commit/query/release。没有声明 mmap 或添加成功占位。

页后端记录最多32个原始区域句柄，拒绝非页对齐、溢出、部分区域和间隙释放。
上层合并两个连续块后，仍按原始句柄释放；提交失败先回滚 reservation。
单用户任务和私有地址空间由真实进程信息验证，不支持并行用户线程或异步信号。

`probe/` 是实际客体使用的四份夹具。32MiB/单CPU与64MiB/四CPU两次冷启动共
执行12个任务，每个完成91项检查，覆盖构造函数阶段调用、地址复用、连续块合并、
非空arena拒绝删除、C堆耗尽、区域配额和页配额耗尽后恢复。另测算术溢出、重复
释放、分配失败的真实abort，以及取消时两块仍存活的60000字节分配。
14次回收均精确返回物理帧基线，私有CR3、整型同伴及内核持续运行。
日志审查拒绝508份缺行、重复行和字段篡改样本。

页后端不调用malloc；首次初始化真实TLS身份仍使用64KiB C堆。不能宣称整个
分配器冷启动与堆无关。完整调用链栈上界尚未证明。

第33次真实GN链接替换6个受影响对象并增加1个页后端对象；5149条旧编译命令、
引擎配置及旧输入顺序保留，缓存只读。LowLevelAlloc缺符号消失，新首错是
`std::__gtos_isolate_diagnostic::mutex::lock()`，来自Abseil的StdcppWaiter。
完整ELF、Isolate/JS、浏览器、视频和HTML5仍未运行。

源码覆盖和SDK位于[集成模块](../native_v8_integration/README.md)，原上游保持不变。
固定工具与输入哈希见[验收记录](acceptance.json)。本次重放脚本和原始日志保留在
工作区 `artifacts/native-low-level-alloc-20261013-a`；夹具依赖实际GN对象及锁定工具链，
尚未提供独立的新主机bootstrap或通用参数化客体入口。
仓库包1285个文件已与隔离源视图校验一致，实际GN重编译的7个对象与私有客体对象
逐字节一致，四份公开夹具也保持原字节。此步骤复用已锁定的prepare-04源视图，
只实体化本模块8个改动，不等于新主机冷构建。第一次仓库终验因文档输入变动被
排除；第二次修正退出判定、更新输入锁后，编译与最终输入复核全部通过。
后续运行须遵循[执行栅栏](../../docs/native-command-execution.md)。
