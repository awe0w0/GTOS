# 自审记录

## 根因与竞争解释

实际完整目标的 `flags.o` 调用 `OS::SetDataReadOnly(&v8_flags,sizeof(v8_flags))`。
缺失并非动态 VM 预留失败；仅提供符号、返回成功、沿用动态区域查询或允许任意
静态页修改都不能满足真实调用与权限边界。原有 `ProtectPage` 只供加载阶段使用。
因此增加单向、独立版本的静态数据服务，复用现有所有权、页表和调度约束。

## 推演与代码核对

1. 第二页有效而第三页为空洞时必须整体失败：先核对加载数据范围，再检查完整
   布局及每页驻留/区域，后续修改阶段没有分配或可失败操作。客机确认前两页仍可写。
2. 请求放在其目标数据页内时，修改 PTE 后不能再读取未复制字段或写回用户结果：
   请求先复制到内核局部变量，返回值仅写 CPUState。真实自覆盖探针通过。
3. `region=0` 同时包含初始栈，不能作为唯一资格：加载器额外记录非执行 PT_LOAD
   的整页范围；ELF 校验已排除跨页重叠、溢出、W+X和保留栈区域。NativeImage
   明确登记独立数据页。系统调用采用当前线程的所属进程，无外部身份选择。
4. 冻结后重复调用不得改变内容或分配资源；PTE保留物理帧、访问/脏位及映射，
   所有权元数据同步变只读。旧动态 VM 接口不能用无效静态句柄恢复可写。
5. 共享线程曾写入后可能持有可写 TLB：修改时执行 `invlpg`，原生任务当前仅在
   BSP 调度；真实工作线程预热写入、读取和幂等调用后触发精确 PF7，整组回收。
6. `Slot` 布局变化会影响缓存消费者：依现有依赖文件重编译5个受影响内核对象。
   实际 GN 图和参数保持，完整链接替换38成员平台档案中的唯一平台对象。

已绑定输入和旧缓存元数据未变，诊断未穷尽。其余约14k原始编译输入未重哈希，
本次核对实际链接文件及新提供者的完整依赖闭包，并保留既有来源证据。

私有失败运行均保留：缺少预处理头路径、未锁定补充头、遗漏实际GN诊断开关、

blob与SHA验证，修正采用新目录；消费者对象复用已合格编译结果，只重新链接。

执行遵守本地命令栅栏：静态审查脚本、固定工具和输入哈希、最小环境、无网络
命名空间、no_new_privs及确切执行/写入白名单，失败即停止，不清理缓存或凭据。
