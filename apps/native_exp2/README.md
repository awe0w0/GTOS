# 原生 exp2

完整 V8 目标的 GC 吞吐量衰减需要真实 C `exp2`。本模块加入固定 LLVM
实现及完整精度回退，沿用实际 i686/SSE2 GN 配置、public packaging 和
线程 errno 提供者。原5183条对象命令及最终输入顺序保持，仅新增一个对象。

GTOS IA32 对 `|x| <= 2^-1022` 使用 `1+x`，解决非FMA的 `x/2` 将最小负
次正规输入舍入成负零、导致向零结果错误的问题。其余 LLVM 算法保持。
正负零仍返回1；非零极小输入产生inexact，避免新增underflow。

参考值由独立400/480位 Decimal 计算及精确有理数边界生成，不调用目标。
58项数据包含非整数、正负零、无穷、quiet NaN分类、范围阈值相邻输入及
适配边界；默认两组还枚举全部2098个可表示整数指数，每组四种舍入模式。
这不是所有IEEE输入的形式化舍入证明，也不声明signaling NaN行为。

32MiB/1配置CPU与64MiB/4配置CPU的默认及多线程客机通过。默认每个上下文
8856次调用，多线程每个上下文464次边界调用；合计52048次、76个实际
CPL3上下文、76次精确回收、48次正常Join。检查errno、x87/MXCSR控制、
要求的异常、sticky invalid及yield后的状态。取消、实际TLS OOM、页故障
和共享errno/TLS反例均通过。配置4 CPU仍采用BSP原生调度。

旧QEMU下显式SSE溢出未报告异常位。相同内核/ELF在既有官方QEMU8.2.2
通过该对照，并暴露上述真实数值错误。旧失败和过度重复整数枚举造成的
宿主超时全部保留；轻量矩阵保留默认完整数值域和所有线程边界/回收条件。

实际完整49链接首错为 `std::__gtos_isolate_diagnostic::cout`，诊断仍未
穷尽。完整原生ELF、Isolate、JavaScript、浏览器、视频和HTML5尚未完成。
生产镜像未改，没有全调用链栈界或物理硬件验收声明。

`probe/` 保存实际验收源码，`reference-source.py` 保存独立参考算法的本次
固定入口；其路径和隔离入口属于资格包，不能直接当作通用构建命令执行。
验收状态和源码哈希见 `acceptance.json`，逻辑审查见 `self-review.md`。
公开源码与私有验收输入逐字节一致；没有重新执行公开构建工具或远端CI。

继续遵守仓库的[本地执行栅栏](../../docs/native-command-execution.md)：
固定工具、静态审阅/哈希锁定入口、最小环境、无网络命名空间、no_new_privs、
Landlock精确执行白名单及新输出写权限。保留镜像、缓存和历史失败。
