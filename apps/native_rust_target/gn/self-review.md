# 自审

独立 O2 core 的编译参数与真实 GN O3 行不同，不能直接复用其归档验收。选择先认证
GN 的真实输入和辅助脚本，再生成精确目标图；生成的行只用于逐项比对，实际运行仍
使用静态参数数组。此方式保留真实 Rust 参数、源码、环境与输出协议，并避免 Ninja
隐式触发尚未审阅的宿主脚本。实际 lint action 使用显式隔离 Python，记录该差异。

首次列表核验失败源于 PowerShell 与 Python 排序规则不同。集合相等并不足以跳过
检查；统一序数排序后在新目录重放，保留完整集合比较。代码生成、元数据分类和
输入/符号链接终验均通过才计为成功。生成元数据额外核对前次摘要，args 明确记录。

原候选在导入 rust.gni 时断言 IA32，会误伤 x64 纯 C++ 图。修正能力声明与 JSON
输入边界后，真实 IA32 编译产物全部保持字节相等，x64 资格图生成通过且无 Rust
工具规则。这里只保护原有 x64 图，不宣称 x64 Rust 或客机 ABI 可用。

补丁回放首次受本机 autocrlf 影响，应用后字节不等，因此该次保留为失败。新目录
只为相关 Git 数据处理命令设置 autocrlf=false/eol=lf，没有改全局配置、hooks、
认证或安全设置；补丁检查、实际应用和全部七文件原始字节比较均通过。

本次未改内核、V8、原生运行库或生产镜像，不重复无关客机矩阵。Content 仍缺真正
标准库 OS 后端和共享库边界处理，后续不能把 core 通过提升为 std/浏览器通过。
