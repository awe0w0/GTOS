# 自审

触发本工作的实际失败来自锁定 Content Shell 对 Rust 的依赖。比较过直接填写 Linux
triple、关闭 Rust 和独立 GTOS 目标三条路径；前两条改变真实消费者或误选系统 ABI，
因此使用独立 GTOS 目标。只读 cfg 通过不足以证明代码生成，随后编译包内真实 core。

编译器、driver、schema 和 VERSION 与 DEPS 指定归档的成员摘要一致。730 个标准库
输入按该归档认证，实际 dep-info 必须全部闭合到已绑定输入。归档对象均检查
ELF32、小端、i386、ET_REL；元数据对象单独分类，不能计为生成代码。rmeta 节摘要
必须与独立 rmeta 文件相同。复核重新核对所有输入与路径别名，任何缺失均不置位。

首次归档检查器的错误假定已定位到固定版本的实际源码与 ELF 节；原失败整体保留，
使用独立目录复核已有编译产物，明确记录本次不重编。解析采用分块摘要，避免一次
载入大型元数据。ELF 允许重复节名，只有实际元数据节要求唯一，避免误拒绝 COMDAT
等合法对象。不会以编译器返回 0 或文件存在代替终验结果。

尚未通过完整 GN 图，私有 GN/Rust 工具候选不作为已验收运行时发布。本目录的目标
规格与 core 证明也不表示 C ABI、操作系统服务或客机程序通过。`target_has_threads`
保留事实属性，标准库不受支持的同步路径仍是待处理失败，不能换成空锁或假成功。

本轮未修改内核、原生运行库或 V8 消费者，因此不重复执行无关客机矩阵。生产镜像
未改。后续真实 Rust OS 后端及 Content 消费者必须另行通过必要客机与回收验收。
