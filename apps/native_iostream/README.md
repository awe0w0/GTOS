# 原生标准流与四上下文同步

本模块接入固定 libc++ 的真实 `iostream.cpp`，验证原生程序在 main 之前初始化标准流，以及返回、`exit`、关闭流和异常终止后的输出与资源回收。它是 32 位 Chromium/V8 原生依赖的一部分；完整 V8 ELF、Isolate、JavaScript、浏览器、视频和 HTML5 尚未通过。

## 实现范围

- 使用固定上游 libc++ 标准流实现，保留真实 rdbuf、tie、unitbuf 和全局初始化/析构。
- 通过真实 LLVM libc File 方法实现 `getc/getwc/ungetwc/fputwc` 边界，保留字节/宽字符方向、EOF、错误状态和 pushback 语义。
- UTF-8 转换拒绝代理码点、过长编码、非法/截断序列和大于 U+10FFFF 的值；合法边界和非字符码点按 Unicode 标量语义处理。
- 增量 `mbrtowc` 立即拒绝不可能成立的首字节和第二字节，合法前缀逐字节恢复并保留 errno；错误或完成后转换状态清零，输入不完整时输出保持原值。
- FILE mutex、外部 libc++ mutex/recursive mutex、std/external once 和 condition_variable 适配已有 GTOS 原生 1/4 上下文服务。锁和 pending 状态标记真实线程 ID，争用时进行真实 scheduler yield。
- 条件变量使用地址空间内 4 个等待记录，通知选择一个或全部等待者；等待结束后重新取得调用者 mutex，保留 errno 和真实时钟错误。

四上下文运行仍在 BSP 上调度。64M/smp4 控制用于检查启动配置变化，不能据此声明原生用户态 SMP 已支持。FILE mutex 保持 12 字节、外部 mutex 保持 8 字节、once 保持 4 字节、condition_variable 保持 8 字节布局。

## 验证证据

- 默认标准流控制：32M/smp1 与 64M/smp4，共 8 个实际 CPL3 程序及 8 次精确回收。
- 四上下文标准流控制：8 组 root+3 worker，共 32 个实际上下文、24 次 Join 和 8 次进程 Reap；独立内核读回两份 24 字节文件，每个线程的 8 字节含 NUL 记录无交错、无重复。
- 原条件变量回归：12 个实际 CPL3 程序、648 项检查和 14 次精确回收，覆盖超时、取消、未持锁终止、时钟耗尽、errno 和重新持锁。
- once 回归：16 个实际 CPL3 程序、18 次精确回收，覆盖重复调用、嵌套、重入、无效状态、空回调、回调页故障和执行中取消。该控制采用历史小型原生入口，完整入口另由标准流控制验证。
- 修改头文件的 62 个保守候选使用者已分类并重编；两处宏选头采用实际完整编译器依赖核对。此审查针对修改头的使用范围，不表示重新编译全部 5187 个 GN 对象。

正常返回 17、C exit 29、关闭 stdout 后 badbit/原生 exit 33，以及主动 abort `0x48000021` 均有独立记录。历史 `GTOS NATIVE HEAP FAIL V1` 字样用于该主动终止诊断，不能视作真实内存耗尽证据。

源码和探针的精确字节对应、输入哈希、实际 GN 参数、完整 M/MD、来源和资源基线见验收记录。生产镜像未改；私有无网 QEMU 控制不能当作可见生产虚拟机更新。后续继续补齐真实完整链接报告的缺失依赖，再推进完整原生浏览器目标。

自审补充的增量控制覆盖 8 个非法一/二字节前缀及 6 个合法标量边界。旧提供者在两配置的 `C0` 第 33 行断言处 exit 91，无 CPU fault；修正组合在默认与四上下文共 16 个场景中通过。这是新边界用例揭示的真实回归，不把此前完整字符测试当作增量语义证明。

最终 full-link-54 保持真实 GN 顺序，重用已核对对象并纳入 14 个增量转换修正对象；7724 项输入和旧缓存终验通过。链接仍为 exit 1，首个缺失为 `OS::GetLastError()`，20 个错误的诊断上限尚未穷尽依赖。同步和 once 回归早于最后格式化及增量转换重编，其范围分别保留，最终标准流场景使用新对象。
