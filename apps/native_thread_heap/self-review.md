# 自审与根因证据

竞争解释是仅更换TLS表即可启用线程；实际堆的arena发布/拆合/回收仍无同步，
该解释不能保证首次TLS分配安全。旧heap反例在同一真实切换点产生0x48000002，
新heap保持同一数据/消费者、通过真实等待和资源回收，证明修改触及实际缺口。

- 原子CAS获得，release store释放；失败实际Yield，BSP等待者不能堵住持锁者。
- RAII覆盖正常early return；malloc/free/realloc/对齐分配和query共享同一锁。
- realloc内部不再次调用公共free，避免自锁；移动拷贝及失败保持行为通过。
- calloc只清理已分配的独占块。caller非法并发free仍不能视作受支持的所有权。
- 目前errno3是无分配共享后端，未宣称线程隔离。未来errno实现也必须无分配，
  不能令持堆锁的错误处理递归调用malloc。TLS和析构列表尚未迁移。
- 真实持锁输出页故障终止整组，随后全部栈/heap/FP回收；不支持独立杀死锁owner
  并保留剩余进程。本次没有假成功Thread或删除one-task保护条件。
- 新/旧提供者均链接同一真实API消费者，保留负例日志；实际分配字节、移动、
  对齐、OOM和回收检查覆盖4上下文。默认FOpen行为另跑并通过。

不把合计32个正常资格上下文解释为TLS/errno/V8线程或浏览器已成功。
公开对应和正常dev提交仅在全部终态通过后执行，缓存与失败保留。
