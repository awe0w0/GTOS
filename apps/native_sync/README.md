# 原生同步库

第33次真实 V8 原生链接缺少 StdcppWaiter 使用的 `std::mutex::lock()` 和条件变量。
集成目标现已接入固定 libc++ 的 mutex/condition_variable 四份原始实现，以及
GTOS 等待后端。现有 owner/depth 锁、真实 realtime 时钟与 scheduler yield 保持
实际语义：参数错误发生在解锁之前，超时和时钟错误后重新持锁，等待前的通知不
留下可消费的通知，无限等待持续让出 CPU，直到所属进程取消。

这份后端只支持 ABI1 的私有地址空间单用户任务，每次改变状态都核对真实进程
能力。四 CPU 测试不代表四个并行用户线程；真实共享地址空间线程、跨线程通知、
阻塞唤醒及异步信号仍需后续实现。没有把缺少的线程服务替换成成功占位。

`probe/` 是实际客户机使用的五份夹具。32M/单CPU、64M/四CPU两次冷启动合计
12个任务、648项检查、14次精确回收。每个任务先完成28项原始ABI、15项标准库、
6项真实Abseil waiter检查，并验证私有CPL3资源。覆盖提前Post的两个唤醒计数、
Poke不增加计数、真实30ms超时、持锁恢复、纳秒范围和通知计数回绕；另测未持锁
标准等待的真实终止、无限等待取消、最大合法deadline取消和时钟耗尽后的恢复。
时钟失败仅在测试内核屏蔽中断时注入一次并立即恢复，生产时钟实现未改。
每次Reap均精确返回物理页基线，整型同伴与内核继续执行。

测试内核复用19个已验收生产对象，只重编测试入口；通过完整ISA审计后由QEMU
直接加载Multiboot内核和真实ELF模块。独立日志复审拒绝380个缺行、重复行及字段
篡改反例。所测程序的ELF/栈/页表成本为59页，加两页动态标记；完整调用链栈
上界尚未证明。

第34次真实完整GN链接新增5个对象，保留5150条旧对象命令、引擎参数和原输入
顺序。原同步库缺符号已消失，首错转为 `v8::base::OS::PrintError`；完整ELF、
Isolate/JS、浏览器、视频和HTML5尚未运行，链接诊断仍受默认20项错误上限限制。

初步编译的MMD记录省略了系统头文件；正式复核改用MD，锁定libc++及Clang资源
头文件，并使用浅层私有源视图补齐3个对象、复核2个已有对象。五个对象与初步
编译逐字节一致，7235个绑定输入终验不变。旧失败和未完成运行保留，不计入验收。

固定来源与证据哈希见[验收记录](acceptance.json)，适配源码位于
[集成模块](../native_v8_integration/README.md)。执行遵循
[安全栅栏](../../docs/native-command-execution.md)。本轮重放复用锁定工作区，尚未
提供独立的新主机bootstrap；生产镜像和磁盘没有更新。
