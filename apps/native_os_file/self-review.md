# 自审记录

## 推演与实现检查

- 普通命名文件直到 fclose 才删除无法覆盖故障或取消。采用原生排他创建加同调用 unlink；验证真实 LittleFS 打开文件在删除目录项后仍可读写，内核 Reap 可以回收。
- 可预测名字必须保持排他创建，不能截断碰撞文件。进程 ID 与原子序号减少碰撞，最多重试 64 次，最大序号处返回 EOVERFLOW，不回绕。测试预占首个名字，检查原字节未变。
- 先打开再分配 FILE 会让 OOM 创建或截断磁盘文件。共享打开函数保留既有的先分配缓冲和 FILE 顺序，失败时释放已分配对象；成功打开后才加入真实 FILE 列表。
- 64 KiB 原生堆无法同时容纳 64 个有缓冲 FILE。旧测试在第 55 个分配处失败；修订测试要求实际 ENOMEM，释放全部 FILE 后再创建成功。随后用 64 个原生句柄单独耗尽内核表，要求 tmpfile 返回 EMFILE 并能恢复。未降低内核句柄边界。
- 临时文件标志进入 LittleFS 前被移除；只有精确的读写、创建、排他组合合法。无效组合在 ATA I/O 之前拒绝；只读检查早于创建。SDK 与内核标志同步，不改变结构布局。
- 同一 IF-clear BSP 操作包含创建和 unlink，其他原生任务不能在中间插入。此论证依赖现有 BSP 调度范围，不宣称用户态 SMP。
- 正常 close 从全局 FILE 列表移除并释放缓冲/对象；异常停止保留内核句柄直至安全 Reap，不能从受害任务栈上销毁地址空间。

## 夹具检查

测试夹具保留独立内核观察：验证请求的用户页、真实 owner 和返回句柄，Stat 必须在同次陷阱返回前报告路径不存在。只读测试卸载空句柄卷后真实只读挂载，检查打开无写入、无句柄，再恢复可写挂载。

旧夹具主动注入 I/O 错误却要求累计错误计数为零。最终夹具要求每个完整程序恰好一次，共四次，不放宽磁盘回调或句柄检查。旧运行和输入保留，不覆盖失败。

故障使用用户态 UD2，要求 vector 6 与退出码 0x80000006；取消使用安全内核上下文的 RequestExit，要求退出码 0x43，重复取消拒绝。两条路径均保留实际已写入 1025 字节的匿名文件，核对一次 Reap 精确恢复文件、页和 FP owner。

新增两条停止路径后，四个 root+3 worker 场景已使用 16 个 ID，后续 root 为 17、18。旧观察数组只容纳 16 个 ID，因而在第五个程序 admission 检查处停止。最终观察数组使用 32 槽并保留显式边界检查；不改变运行时 ID 分配、可用句柄或回收断言。旧失败保留。

## 证据范围

来源与公开文件逐字节对应，提供者采用实际 GN 参数和完整 M/MD；内核保持 GP-only 指令限制。完整链接保持上一版实际 GN 顺序，只替换两个已有用户态提供者，重用哈希锁定的 38 成员归档。链接仍可能报告下一批真实缺失依赖，20 个错误上限并非全部依赖清单。

完整 V8 ELF、Isolate、浏览器、视频及 HTML5 的结果以验收记录为准，不能用这些独立消费者代替。生产镜像、可见虚拟机和远程 CI 未因本模块更新。
