# 真实 V8 负载运行的重放入口

本目录把"当前源码构建诊断内核 + 用固定镜像在其上真实运行 V8 负载"固定成可重放的脚本，不含任何预置产物。四个文件各管一件事：

- `kernel.py` —— 从**当前源码**编译 21 个目标（16 个运行库单元 + 观测器 + 4 个汇编入口），用 `llvm-nm` 从固定镜像读出 5 个状态符号写成 `entry-symbols.h`（内核与它要驱动的镜像绑在同一份字节上），按本树自己的诊断配方链接，并跑本树的指令审计。构建记录里写明每个 TU 的源码哈希、编译器自己的 `-MD` 依赖文件里的实际头文件及其哈希、flags、工具版本与权限位、符号头、内核产物和全部内容的 digest。
- `guest.py` —— 两种模式共用一个判定器：`guest.py` 起动客人并判定；`guest.py judge <log> [status]` 只对已有日志做同一判定（供测试与只读复核），不启动任何东西。判定要求每条记录都齐全、只出现一次、数值可解，`reap` 必须同时给出 `free` 与 `baseline` 才能比较。
- `replay.sh` —— 每次运行建一个**独占**目录（`<GTOS_OUT>/run-<UTC>`），把内核构建 stdout/stderr、客人 E9 原件、QEMU stderr、客人自身 stdout 和结果 JSON 分成不同文件；已存在的目录一律拒绝，不覆盖旧证据。构建前先比对固定镜像的 sha256/字节数。
- `test-judge.sh` —— 用真实 E9 原件做单条件变异，交给同一个 `guest.py` 判定，并验证启动前条件（已有证据、工具权限位、镜像身份）。

## 串口

本观察器**只向 E9 调试口输出**，当前 QEMU 命令行为 `-serial none`，因此本次诊断**没有串口采集**。这一点在结果 JSON 的 `serial` 字段里如实写明，不复制 E9 冒充串口，也不为迁就旧格式增加无关 UART 工作。

## 边界

- 只跑 jitless、单用户线程的负载；不含 Wasm、ICU、沙箱，也没有多线程 GC。
- 通过的是**这个负载在这个内核上**的生命周期，不是浏览器可运行、不是四作业 CI 复跑、不是远端验证。
- 工具与镜像由调用方给出并绑定身份；脚本自己不 chmod 工具，权限位不对就停下并说明由供给阶段提供。
- 同一个源码树三次构建得到过三个不同内核哈希（`f1c3dcd6`、`b4014298`、`a1c53686`）；绑定按每次运行记录，不宣称可重复构建。
