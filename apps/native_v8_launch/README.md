# GTOS 原生 IA32 V8 脚本运行

后续完整62的[工作负载补验](workloads/README.md)已在同一真实引擎中覆盖对象/数组、
TypedArray/DataView、真实GC、显式Promise微任务及异常恢复；其双配置机器证据与
原始日志单独保存在子目录。下文完整61保留堆、启动配置及基础表达式的验收历史。

锁定的完整 V8 ELF 已在 GTOS CPL3 中实际创建 Isolate、Context，编译并执行
`'GTOS' + (40 + 2)` 和 `1.25 + 2.5`，分别检查得到 `GTOS42`、`3.75`。
两个配置均以 stage=4、result=0、exit=0、无故障结束，并精确回收进程物理页。
这是单用户线程、jitless、关闭 Wasm/ICU/sandbox 的 V8 验收；Chromium Content、
网页浏览、视频和 HTML5 尚未运行，冷构建及空白主机 bootstrap 尚未验收。

## 实现与边界

完整61 ELF 为 12,932,528 字节，2385 个装载页。真实 GN 配置与原有对象缓存
保留，共1110个链接输入，只替换堆和启动入口对象；其余1108个输入及所有归档
的字节、顺序、缓存元数据均通过终验。入口在全局初始化前显式启用后备堆。

默认 C 堆仍为一个64KiB arena。显式完整 V8 配置最多添加七个按需64KiB arena，
将不超过16KiB、对齐不超过4KiB的小块打包；大请求最多使用16个独立映射，每次
最多1MiB。先预留、提交成功后才发布所有权；失败撤销预留。free只接受精确活
payload，最后一块释放整个arena。realloc保留对齐与旧数据，失败不更改旧块。
所有元数据操作与复制仍在原有HeapGuard内。query仅报告主arena。

`NativeElfLaunchProfile` 是可信内核选择，用户系统调用不能提高预算。根栈2–128页、
运行页1–1024页，总容量必须在256–4354条所有权记录内。完整 V8 使用
`{4096,128,1024}`：2385镜像页+128根栈页+1024运行页=3537条，元数据14帧。
普通三参数CreateElf及旧镜像页数重载保留各自原语义。单次VM事务仍限制256页。

每进程动态映射上界停在实际根栈下方guard之前；Prepare核对上界，Reserve的
长度、hint及搜索均服从该值，Destroy恢复默认。ELF不能覆盖栈和两端guard。
slot和PROCESS_INFO报告实际栈边界，V8平台取得同一事实。当前IA32 V8默认栈
472KiB，另留40KiB余量，匹配512KiB映射。

地址空间全量检查每次重建两个8192槽临时索引，精确检查VA及物理页唯一性，
完整PTE检查按索引查找权威记录。保留页表、所有权、别名、权限、区域与内核
模板检查；没有缓存“通过”的结果。64KiB临时工作区位于内核BSS，由既有BSP
中断保护串行使用，不属于进程所有权，不支持AP进入此地址空间管理器。

## 验证

- 完整V8：32MiB/smp4、64MiB/smp1，各3557次系统调用，stage4/result0/exit0。
  初始2513驻留页，退出时2531驻留页，其中动态18页；独立大块全空，剩余进程
  静态/运行资源由Reap归还。空闲帧分别精确恢复4427、12611。
- 分配器边界：32MiB/smp1、64MiB/smp4，各五场景；正常各372736断言，动态页
  归零。覆盖多arena、对齐、重分配、清零、溢出、槽耗尽/复用、40次提交失败
  的预留回收、内点/重复释放、UD2和外部取消。
- 启动边界：非法字段/总容量、ELF覆盖扩展栈或guard、动态末页及越界、物理
  OOM中途回滚、真实高低guard页故障、取消及同槽恢复默认256页/8KiB栈。
- 索引反例：不同VA散列碰撞正常读写；重复VA、重复物理所有权、无权威记录
  的PTE及权限不一致均被拒绝，恢复后可正常销毁。两配置全部通过。
- 共享堆：两配置合计24上下文；每次强制在真实Reserve返回后持锁切换，其他
  上下文实际Yield等待。跨arena重分配、Join、整组取消及持锁输出故障后精确
  回收，FP初始化与失效计数一致。该夹具不重新声明每线程errno资格。
- 默认入口回归：single/thread各32MiB/smp1和64MiB/smp4，共44程序、68上下文、
  24次Join、44次Reap，文件句柄、FP及物理帧全部恢复基线。

机器证据见 `acceptance.json`；原始客机日志与内核/共享堆夹具保留在本目录。
私有完整依赖、工具、命令、输入终验及失败在工作区
`artifacts/native-large-heap-20261015-a` 与 `artifacts/native-v8-launch-20261015-a`。
生产镜像尚未更新，不能把本模块记为桌面浏览器启动。

## 失败记录与下一步

原64KiB堆不足以满足Isolate对齐分配；初版每小块独立一页会耗尽16槽；256运行
页预算也实际拒绝194+64页。修订后又触及8KiB根栈guard。显式栈/运行预算解决
准入后，旧全量检查的二次复杂度使完整运行分别触发300/600秒宿主超时。
寄存器样本和持续增加的系统调用证明它在Layout中推进；索引版本约83秒完成
含编译与终验的诊断运行。并发宿主任务存在，不能据此声明稳定性能倍率。

下一步按原路线推进真实Chromium Content本地首帧和DOM，再接受控网络及音视频。
不将V8脚本成功替代网页、视频、Wasm、通用SMP或HTML5的验收。
